# Change Request

## 為什麼 TPM 要會？

客戶突然加需求時，不要先回答能不能做。你要先說清楚：可以評估，但需要看 scope、schedule、cost、risk 與 approval。

## 影響分析

- Scope：原本承諾是否改變？
- Schedule：是否影響里程碑或 UAT？
- Cost：是否需要新增人力或費用？
- Risk：是否引入未知技術或外部依賴？
- Approval：誰能同意這個變更？

## 建議回覆

```text
這項需求我們可以納入變更評估。
我會先確認影響範圍、時程與風險，整理選項後再請雙方決策。
在核准前，我不會把它視為已承諾 scope。
```
